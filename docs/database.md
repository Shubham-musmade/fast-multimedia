# Database & Migrations — fast-multimedia

This document explains how the database is configured and how migrations are created and applied in this project.

## Overview
- The application uses SQLAlchemy 2 with the async driver `asyncpg` for runtime database access.
- Alembic is used for schema migrations (synchronous operations).
- Models live under `app/models/` and use the SQLAlchemy declarative base.

## Configuration
- Environment variables are loaded from `.env` via `pydantic-settings`.
- Key variable: `DATABASE_URL` — example value in `.env`:

  DATABASE_URL=postgresql+asyncpg://postgres:password@localhost:5432/media_db

- NOTE: runtime code uses the `asyncpg` URL. Alembic (sync) requires a sync driver (psycopg). The project converts the URL for Alembic.

## SQLAlchemy setup (runtime)
- File: `app/core/database.py`
- The async engine is created with `create_async_engine(settings.DATABASE_URL)`.
- Async session factory: `AsyncSessionLocal = async_sessionmaker(...)`.
- Dependency for FastAPI routes: `get_db()` yields an `AsyncSession`.

Example (already in repo):

```py
engine = create_async_engine(settings.DATABASE_URL, ...)
AsyncSessionLocal = async_sessionmaker(bind=engine, expire_on_commit=False)
async def get_db():
    async with AsyncSessionLocal() as session:
        yield session
```

## Models
- Models use a declarative base in `app/models/media.py`:

  Base = declarative_base()

- Alembic autogeneration needs `target_metadata` set to the `Base.metadata` used by your models.

## Alembic (migrations)
- Alembic config file: `alembic.ini`.
- Migration scripts and env: `alembic/versions/` and `alembic/env.py`.

Important changes in this project:
- `alembic/env.py` imports application settings and model metadata, and converts the async URL into a sync URL for Alembic:

```py
from app.core.config import settings
from app.models.media import Base
config.set_main_option("sqlalchemy.url", settings.DATABASE_URL.replace("+asyncpg", "+psycopg"))
target_metadata = Base.metadata
```

Why: Alembic runs synchronously and requires a DB-API driver compatible with SQLAlchemy's sync engine (psycopg). The app itself runs async against `asyncpg`.

### Common Alembic Commands
- Activate your virtualenv:

```bash
source .venv/bin/activate
```

- Create an autogenerated migration (inspects models vs DB and creates a revision):

```bash
.venv/bin/alembic revision --autogenerate -m "describe change"
```

- Apply migrations to the database:

```bash
.venv/bin/alembic upgrade head
```

- Check current DB revision:

```bash
.venv/bin/alembic current
```

### Troubleshooting
- ModuleNotFoundError: No module named 'psycopg'
  - Fix: install the sync driver in the project venv: `.venv/bin/pip install "psycopg[binary]"`.
  - Optionally add `psycopg[binary]` to `requirements.txt` so teammates/CI install it automatically.

- ERROR: Target database is not up to date.
  - This occurs when alembic autogenerate detects the DB has unapplied revisions. Run `.venv/bin/alembic upgrade head` first to sync.

- Autogenerate diffs appear unexpected:
  - Ensure `target_metadata` points to the same `Base.metadata` used by your models.
  - Check for differences caused by default functions vs server defaults (e.g., `func.now()`), and adjust models or the generated migration manually.

## Verification
- After running migrations, you can verify tables exist with a small script:

```bash
.venv/bin/python3 - <<'PY'
from app.core.config import settings
from sqlalchemy import create_engine, inspect
sync = settings.DATABASE_URL.replace('+asyncpg', '+psycopg')
engine = create_engine(sync)
inspector = inspect(engine)
print('tables:', inspector.get_table_names())
PY
```

Expected output should include `alembic_version` and your model tables (e.g., `media_assets`).

## CI / Deployment notes
- Ensure the environment variable `DATABASE_URL` is set in production.
- Ensure the sync driver (`psycopg[binary]`) is installed in CI and deploy images if your deployment runs Alembic migrations during startup.
